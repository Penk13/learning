The durable core of Topic 1: prompts, paths, streams, pipes, quoting, globs, and the mental model that makes them one system.

Print-friendly bash Lesson 0001

The model

Command = program + arguments. The shell splits the line, finds the program on $PATH, runs it, and its text output flows to the terminal — or through pipes into the next program.

Prompt & navigation

missing:~$            # user@machine:directory — $ means not root
pwd                   # print working directory
cd /path/to/dir       # change directory (shell builtin!)
cd ~  /  ..           # home / root / parent;  .  = this directory
echo $PWD             # same as pwd
ls -l /               # first 10 chars = type + permissions (-rw-r--r--)

Finding & learning programs

echo $PATH            # ':'-separated dirs the shell searches, in order
which date            # which file will run for 'date'
man date              # manual page (space to page, q to quit)
date --help           # most programs accept --help
tldr date             # (install) quick examples

Streams, redirection, pipes

Every program has stdin (0), stdout (1), stderr (2).

cmd > file            # stdout → file (overwrite)
cmd >> file           # stdout → file (append)
cmd < file            # stdin ← file
cmd 2> err.txt        # stderr → file
cmd > all.txt 2>&1    # both streams → same file
cmd | other           # pipe: stdout of cmd → stdin of other
cmd | tee log.txt     # show AND save; e.g. migrate | tee deploy.log

Exit status & control operators

cmd; echo $?          # 0 = success, non-zero = failure
cmd1 && cmd2          # run cmd2 only if cmd1 succeeded
cmd1 || cmd2          # run cmd2 only if cmd1 failed
# CI pattern: npm test && npm run build

Quoting

'literal $PATH'       # single quotes: everything literal
"double $PATH"        # double quotes: variables expand
My\ Photos            # escape a single special character
$'line\nbreak'        # ANSI quotes: escape sequences (see Bash manual)

Globs (shell expands before the program runs)

ls *.txt              # any characters
ls file?.txt          # exactly one character
ls {a,b,c}.txt        # brace expansion: a.txt b.txt c.txt

Everyday text tools

cat fileprint file
sort fileprint sorted lines
uniq -c filecount consecutive duplicates
head / tail filefirst / last lines
grep pattern filematching lines (pattern = regex)
sed -i 's/a/b/g' filereplace all occurrences in place
find . -name "*.py"find files by name/type/size
awk '{print $2}' fileprint a column of every line

Composition example: find the 5 most common extensions in your home directory — find ~ -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn | head -5.

Scripting starters

#!/bin/bash           # shebang: runs the file with bash
set -euo pipefail     # strict mode: fail on error/undefined var/broken pipe
for i in $(seq 1 10); do echo "$i"; done
if [ -f "$1" ]; then echo "exists"; else echo "missing"; fi
./script.sh           # needs executable bit: chmod +x script.sh

Pitfalls

  • cd must be a builtin: a child process cannot change its parent's directory.
  • Quote variables ("$1") — filenames with spaces will break unquoted scripts.
  • Check scripts with shellcheck before trusting them.
  • bash has many gotchas; >100-line "scripts" are usually better rewritten in Python.
