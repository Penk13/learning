Dotfiles Repo and Installing Tools

Keep your config in Git, symlink it into place, keep secrets out, and read installers before you run them.

Organising dotfiles

~/dotfiles/              ← a Git repo
  bashrc
  gitconfig
  tmux.conf
  install.sh             ← creates symlinks:
                             ln -sf ~/dotfiles/bashrc ~/.bashrc
                             ln -sf ~/dotfiles/tmux.conf ~/.tmux.conf

The real files live in one version-controlled folder; symlinks put them where programs expect them. You get one-command setup on a new machine, the same behaviour everywhere, easy syncing, and a history of every change. Read other people's dotfiles for ideas, but don't copy whole configs blindly.

Secrets stay out

Dotfiles repos are often public. Never put tokens, passwords or export API_KEY=… in them, and never commit ~/.ssh/ private keys. Keep secrets in a separate, uncommitted file that .bashrc sources only if it exists, or in a secret manager:

[ -f ~/.bashrc.local ] && source ~/.bashrc.local

Package managers

$ sudo apt install ripgrep fd-find tldr   # Ubuntu/WSL
$ rg "TODO" src/                          # ripgrep: faster grep
$ tldr tar                                # example-first help

Package managers download, install and update for you: apt on Ubuntu/WSL, Homebrew on macOS, dnf, pacman. Names vary: on Ubuntu, fd is packaged as fd-find and the command is fdfind. Check with apt search. On a work laptop or server, follow your team's approved-software process first.

The curl | bash warning

# convenient but blind:
curl -fsSL https://example.com/install.sh | bash
# safer: download → read → run
curl -fsSL https://example.com/install.sh -o install.sh
less install.sh
bash install.sh

Piping straight into bash runs code you have never seen, with your permissions. The same rule applies to commands an AI tool generates for you: read before you run.

Shells, plugins, terminals (brief)

  • zsh plugins: syntax highlighting, autosuggestions, prompt themes. Single plugins instead of a big framework like oh-my-zsh keep startup fast. fish has many of these built in.
  • AI in the shell: tools can turn English into commands, process messy text in a pipeline, or act as a whole "meta-shell".
  • Terminal emulator: the window your shell runs in (on Windows, usually Windows Terminal). Tune font, colours, scrollback.

Check yourself

You get a fresh WSL install and already have a ~/dotfiles Git repo with an install script.

Describe how the repo gets your shell back to normal. Use the words symlink, startup, current shell and secrets.

Clone the repo and run its install script, which symlinks each file (e.g. bashrc → ~/.bashrc) into place. Bash reads ~/.bashrc at startup, so new terminals get the aliases, functions and PATH; an already-open terminal needs source ~/.bashrc to apply them in the current shell. Secrets were never in the repo; restore them from an uncommitted local file or a secret manager.

What belongs in a public dotfiles repo?

Version-control your configuration, not your credentials. Load secrets from an uncommitted local file or a secret manager.

An install guide says to run curl -fsSL https://example.com/install.sh | bash. What is the risk, and what do you do instead?

It runs a script you have never read, with your permissions. Download it to a file (curl … -o install.sh), read it (less install.sh), then run it with bash install.sh.
