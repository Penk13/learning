Job Control and Cleanup

Foreground, background, suspended: one shell juggles many jobs, and they all die with the terminal unless you plan for it.

Jobs

A job is a command your current shell started. Only one job owns the keyboard (the foreground); others run in the background or are suspended (paused).

$ sleep 1000 &             # & = start in background, prompt returns
[1] 18653
$ sleep 2000               # foreground… press Ctrl-Z
[2]+ Stopped     sleep 2000
$ jobs                     # list this shell's jobs
$ bg %2                    # resume job 2 in the background
$ fg %1                    # bring job 1 to the foreground
$ kill %2                  # %N works wherever a PID does
$ echo $!                  # PID of the last background job

Common move: you started something long and forgot &. Press Ctrl-Z (suspend), then bg. A background job still writes to your terminal, so redirect noisy ones: long-task > task.log 2>&1 &.

Surviving a closed terminal

Background jobs are still children of the terminal's shell. Closing the terminal sends them SIGHUP and they die. & only means "don't wait for it".

ToolWhenWhat it does
nohup cmd &before startingruns cmd ignoring SIGHUP; output goes to nohup.out
disownjob already runningremoves it from the job table so the shell won't send SIGHUP
tmuxbest optionthe shell itself lives on, detached; you can reattach (see the tmux lesson)

Cleanup in scripts: trap

#!/usr/bin/env bash
set -euo pipefail
tmpdir=$(mktemp -d)
cleanup() { rm -rf "$tmpdir"; }
trap cleanup EXIT   # runs when the script ends, for any reason

trap CMD SIGNALS… runs CMD when the script receives those signals. EXIT is a bash pseudo-signal for "the script is ending"; it also fires after Ctrl-C or kill, so you rarely trap those separately. Nothing runs on SIGKILL, another reason to avoid kill -9.

Waiting for background work

$ sleep 5 &
$ wait            # block until all background children finish
$ wait $!         # or just the last one
$ kill -0 PID     # sends nothing; exit 0 if the process exists

wait only works on your own children. For an unrelated process, poll with kill -0 (the official pidwait exercise).

Try it

  1. sleep 1000, Ctrl-Z, jobs, bg, jobs: watch Stopped become Running.
  2. pkill -f "sleep 1000", then jobs.

Check yourself

In bash you started npm run build without & and want your prompt back without stopping the build. What do you do?

Ctrl-Z suspends it (SIGTSTP); bg resumes it in the background. fg would put it back in the foreground.

You run python long_job.py & in a terminal, then close the terminal window.

What happens to the job by default, and name two ways to keep it alive.

It is still a child of the terminal's shell, so it receives SIGHUP and usually dies; & only means "don't wait". Keep it alive with nohup (at start), disown (already running), or better, run it inside tmux.

In a bash script that creates a temp directory, how do you guarantee it is deleted even if the script fails or is stopped with Ctrl-C, and when does that guarantee not hold?

Define a cleanup function and register it with trap cleanup EXIT; the EXIT trap runs whenever the script ends, including after errors, Ctrl-C (SIGINT) or SIGTERM. It does not run on SIGKILL (kill -9), which can't be caught.
