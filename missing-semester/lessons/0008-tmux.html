tmux: Shells That Survive

tmux owns your shells; your terminal is just a viewer you can close and reopen.

The model

tmux is a server process that owns your shells. Close the viewer, or lose the connection, and the shells keep running. Reattach later and everything is where you left it.

Why it beats & and nohup

With &, a job's parent is the shell belonging to your SSH session. When the connection drops, that shell gets SIGHUP, passes it on, and the job dies. Inside tmux, the shell's parent is the tmux server, which isn't tied to your connection. Unlike nohup, you can reattach and interact again, with live output and full scrollback.

Prefix key and hierarchy

Every shortcut starts with the prefix Ctrl-b: press it, release, then the next key (written <C-b> d).

  • Session: an independent workspace (one per project or task).
  • Window: like a browser tab inside a session.
  • Pane: a split inside a window.
# Sessions (typed in a normal shell)
$ tmux new -s deploy      # new session named "deploy"
$ tmux ls                 # list sessions
$ tmux a                  # attach to the last session
$ tmux a -t deploy        # attach to a specific one
  <C-b> d                 # DETACH: leave it running
# Windows
  <C-b> c                 # new window (exit closes it)
  <C-b> n / p / 0..9      # next / previous / jump to N
  <C-b> ,                 # rename window
# Panes
  <C-b> "  /  %           # split top-bottom / left-right
  <C-b> <arrow>           # move between panes
  <C-b> z                 # zoom current pane (toggle)
  <C-b> [                 # scrollback mode (q to leave)

Where you'd use it

  • Long server tasks: ssh server, tmux new -s migrate, run python manage.py migrate or dotnet ef database update. Connection drops? ssh server, tmux a -t migrate.
  • Local layout: one window with panes for dotnet watch, npm run dev and a free shell. Works the same in WSL.

Try it

  1. tmux new -s play, run top, <C-b> d. Close the terminal window, open a new one, tmux a -t play: is top still running?
  2. tmux kill-session -t play to clean up.

Check yourself

Explain to a teammate why running a long command over SSH inside tmux is safer than running it with &. Use SIGHUP, parent, detach and reattach.

With &, the job's parent is the shell of your SSH session; when the connection drops that shell gets SIGHUP and the job dies. Inside tmux, the shell's parent is the tmux server, which isn't tied to the connection, so you can detach (or lose the network) and the job keeps running. Later you reattach and see its live output and scrollback.

Your SSH connection drops while a database migration runs inside tmux on the server. What state is the migration in?

The shell's parent is the tmux server on the remote machine, which never received a hang-up. Only the viewer (your SSH session) went away.

In tmux, how do you leave a session running and get back to it later? Give the key and the command.

Detach with Ctrl-b then d. Reattach with tmux a (last session) or tmux a -t NAME; tmux ls lists sessions.
