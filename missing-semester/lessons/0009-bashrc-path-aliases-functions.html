.bashrc: PATH, Aliases and Functions

Your shell rebuilds itself from a plain-text file at every start; edit the file to change every future terminal.

The model

Every new interactive bash sources its startup files (mainly ~/.bashrc). Whatever they export, alias or define exists in that shell. To change "my shell", edit the dotfile, then open a new terminal or source it.
open terminal
→
bash sources
~/.bashrc
→
PATH, aliases,
functions, prompt

.bashrc must be sourced, not run: a child process couldn't change your shell. A shell that's already open read the file at startup and won't notice later edits.

Which file?

A dotfile is a plain-text config file whose name starts with ., which hides it from ls (use ls -a). Bash's startup rules are complicated (login vs interactive shells). Practical rule: put aliases, functions, PATH changes and prompt settings in ~/.bashrc. On Ubuntu (including WSL) the default ~/.profile already sources ~/.bashrc for login shells. Other common dotfiles: ~/.gitconfig, ~/.ssh/config, ~/.tmux.conf, ~/.vimrc.

Extending PATH

export PATH="$PATH:$HOME/.dotnet/tools"   # append one folder

Read it as "new PATH = old PATH + one folder, exported so children inherit it". Always keep $PATH in the value: export PATH="/some/dir" alone replaces the list and breaks ls, git and everything else in that shell. If a dotnet tool install -g command isn't found, ~/.dotnet/tools is missing from PATH.

Aliases

alias ll="ls -lh"        # no spaces around =
alias gs="git status"
alias mv="mv -i"         # safer default: ask before overwriting
alias ll                 # show a definition
\ls                      # bypass an alias once
unalias ll               # remove it

An alias is text replacement of the first word. It can't put an argument in the middle; use a function for that.

Functions

mkcd() {                 # make a folder and enter it
    mkdir -p "$1" && cd "$1"
}

Functions take $1, $@ and friends like scripts, but run in the current shell, so their cd and export stick. venv() { source .venv/bin/activate; } works for the same reason. type gs mkcd shows what each name is.

History search

Ctrl-R, then type part of an old command. Ctrl-R again for older matches, Enter to run, an arrow key to edit first. With fzf's shell integration, Ctrl-R becomes a fuzzy list.

Check yourself

You add alias gs="git status" to ~/.bashrc, save, and type gs in the same terminal: "command not found".

Why, and what are the two fixes?

The running shell read .bashrc once, at startup; editing the file doesn't change it. Run source ~/.bashrc or open a new terminal.

An install guide says to add export PATH="/opt/tool/bin" to ~/.bashrc. What goes wrong, and what should the line be?

It replaces the whole PATH, so ls, git and other commands are no longer found in that shell. Keep the existing list: export PATH="$PATH:/opt/tool/bin".

In bash you want mkcd foo to create foo and move your shell into it. Which works?

Aliases can't use arguments in the middle. A script runs in a child, so its cd is lost. A function takes arguments and runs in your current shell.
