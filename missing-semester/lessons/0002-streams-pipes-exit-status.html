Streams, Pipes and Exit Status

Programs talk through three streams and report back one number; the shell lets you rewire both.

Three streams

Every program has stdin (0, input), stdout (1, normal output) and stderr (2, errors). By default all three are connected to your terminal. Redirection reconnects them to files:

$ date > now.txt              # stdout → file (overwrite)
$ date >> log.txt             # stdout → file (append)
$ grep hi < notes.md          # stdin ← file
$ ls /nope 2> err.txt         # stderr → file
$ cmd > all.txt 2>&1          # both streams → same file
$ cmd 2> /dev/null            # throw errors away

Errors go to stderr precisely so they still reach you when stdout is redirected or piped.

Pipes compose programs

A pipe | connects stdout of the left program to stdin of the right one:

$ grep TODO notes.md | wc -l
2

grep keeps only the lines containing TODO; wc -l counts the lines it receives. Two small programs, one task: find then count. That composition is the point of the shell.

tee splits a stream: python manage.py migrate | tee deploy.log shows the output and saves it.

Exit status

Every program exits with a number: 0 = success, anything else = failure. $? holds the last command's status.

$ ls /nope; echo $?     # 2 — failed
$ true  && echo yes     # yes  (&& runs only after success)
$ false || echo no      # no   (|| runs only after failure)
$ false && echo yes     # (nothing — false failed)
$ cmd1 ; cmd2           # ; runs cmd2 regardless
OperatorRight side runs when left…
&&succeeded (status 0)
||failed (non-zero)
;always

npm test && npm run build builds only if the tests passed. CI works the same way: a step fails only because some command exited non-zero.

Quoting and globs

The shell rewrites your line before the program sees it:

$ echo '$PATH'          # $PATH          (single quotes: literal)
$ echo "$PATH"          # /usr/local/... (double quotes: variables expand)
$ ls *.txt              # glob: any characters
$ ls file?.txt          # exactly one character
$ ls {a,b,c}.txt        # brace expansion: a.txt b.txt c.txt

The program receives the already-expanded file names; ls never sees the *.

Try it

  1. ls /nonexistent /tmp > out.txt 2> err.txt, then cat both files.
  2. false && echo yes; false || echo no: predict first, then run.

Check yourself

notes.md contains exactly two lines that include the word TODO.

What does grep TODO notes.md | wc -l print, and what does each part do?

It prints 2. grep writes the two matching lines to its stdout; the pipe feeds them into wc's stdin; wc -l counts lines.

In bash, what does false && echo yes; false || echo no print, and why?

Only no. false exits non-zero (failure). && runs its right side only after success, so echo yes is skipped; || runs its right side only after failure, so echo no runs. ; just separates the two commands.

You run ./deploy.sh > out.log and still see an error message on the terminal. Why?

> only redirects stream 1. Add 2>&1 (after the > out.log) to send stderr to the same file, or 2> err.log to split them.
