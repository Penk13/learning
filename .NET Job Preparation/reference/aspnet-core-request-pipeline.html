ASP.NET Core request pipeline

The compact mental model to use when explaining middleware in an interview.

One sentence

An ASP.NET Core request pipeline is an ordered sequence of request delegates. Each middleware can do work before and after the next delegate, or stop the request by not calling it.

Control flow

1Middleware A
→
2Middleware B
→
3Terminal delegate

Forward path: A before → B before → terminal. Return path: B after → A after.

Vocabulary

Middleware
A component that handles part of a request/response journey and may invoke the next component.
Request delegate
The callable that handles an HTTP request at one point in the pipeline.
Short-circuit
Stopping pipeline traversal by not invoking the next delegate.
Terminal middleware
Middleware that ends traversal; Run creates a terminal delegate.

Interview checklist

  • Middleware runs in registration order on the way in.
  • Code after await next runs while the response unwinds.
  • Order is behavior: exception handling usually belongs early so it can observe later failures.
  • A component that does not call the next delegate short-circuits the pipeline.
  • Use the words ordered, next delegate, before/after, and short-circuit.
