0:00–1:00 · Retrieve first

What happens after a request arrives?

Before reading further, answer aloud or in a note: “How does an ASP.NET Core application decide what code handles an HTTP request?” Do not look anything up yet. A rough answer is useful; it gives us a baseline.

Now reveal the target idea

ASP.NET Core composes an ordered pipeline of request delegates. Each middleware can perform work, call the next delegate, and then perform more work as the response returns—or stop the journey early.

1:00–5:00 · The one idea

A pipeline is a chain with a return trip

Microsoft describes middleware as software assembled into an application pipeline to handle requests and responses. The important interview detail is that middleware has two opportunities: before the next component and after the next component.

Think of the request moving forward through doors, then the response walking back through the same doors. That is why logging or timing code can wrap an endpoint.

5:00–9:00 · Read the code

Use continues; Run can finish

This is a deliberately small version of the pattern shown in the official documentation:

app.Use(async (context, next) =>
{
    Console.WriteLine("A before");
    await next.Invoke(context);
    Console.WriteLine("A after");
});

app.Use(async (context, next) =>
{
    Console.WriteLine("B before");
    await next.Invoke(context);
    Console.WriteLine("B after");
});

app.Run(async context =>
{
    Console.WriteLine("terminal");
    await context.Response.WriteAsync("OK");
});
  • Use receives a next delegate and can choose whether to invoke it.
  • Statements before next run on the way in.
  • Statements after next run on the way back out.
  • Run is terminal here: there is no later delegate to invoke.

The exact overloads can vary with the API shape; focus on the control flow first. The official source linked below is the authority for current syntax.

14:00–18:00 · Interview drill

Answer in 60 seconds

Imagine an interviewer asks: “What is ASP.NET Core middleware, and why does its order matter?” Answer aloud before opening the self-check.

Self-check rubric
  • Define middleware as an ordered chain of request delegates.
  • Say that a component can run before and after the next delegate.
  • Explain short-circuiting: not invoking the next delegate stops traversal.
  • Give one order example, such as exception handling early so it can observe later failures.
