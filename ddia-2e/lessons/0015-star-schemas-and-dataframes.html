Star Schemas and DataFrames

Data models built for analysts and data scientists rather than for app code.

Stars and snowflakes

Data warehouses are usually relational and follow conventions built for analysts. ETL moves operational data into them.

⭐ Star

Fact table in the middle, dimension tables around it, mostly many-to-one. Simpler for analysts, so usually preferred.

❄ Snowflake

Dimensions split into sub-dimensions (brand, category). More normalized, more joins.

📏 One big table (OBT)

Fold the dimensions into the fact table: pre-joined. More storage, sometimes faster queries.

Tables are wide, often 100+ columns, and fact tables can reach petabytes. Denormalizing is fine here because the data is a log of history that rarely changes.

DataFrames, matrices and arrays

These belong to analytics, data science and ML, rarely OLTP. A DataFrame (R, Pandas, Spark) looks like a table and supports filter, group, aggregate and join (called merge). It's driven by a series of commands rather than declarative SQL, which matches how data scientists wrangle a private copy step by step.

Array databases (e.g. TileDB) store huge multidimensional arrays: geospatial rasters, medical imaging, telescope data.

A snowflake is a more normalized star. Star is usually preferred for analyst simplicity; OBT goes the other way and folds dimensions into the fact table.

In a star schema, what goes in the fact table and what goes in the dimension tables?

Fact table: one row per event (e.g. one sale), with measures like price and cost plus foreign keys to dimensions. Dimension tables: the who, what, where, when, how and why of the event, e.g. customer, product, store, date, promotion.

Normalization is the usual default for OLTP. Why is heavy denormalization acceptable in a data warehouse?

Warehouse data is a log of past events that rarely changes and is updated in bulk, so the main cost of denormalization (keeping many copies consistent on every write) barely applies, while analysts gain simpler, faster read queries.

To run ML on a table of (user, movie, rating) plus each movie's genre, how would you turn it into a matrix?

Pivot it into a sparse matrix with users as rows and movies as columns, cells holding ratings (empty where no rating). Matrices hold only numbers, so encode the genre category with one-hot encoding: one 0/1 column per genre.
