Lesson 0001 · React JS job preparation

Render data, not repetition

Use everyday JavaScript—map(), destructuring, and stable IDs—to produce a React list you can explain in an interview.

10–15 minutes JavaScript → React Retrieval + feedback
Why this matters for your mission. Frontend interviews often ask you to render, filter, or update collections. A strong answer connects JavaScript behavior to React behavior: transform data into JSX, preserve item identity with keys, and avoid mutating source arrays.
The mental model

One collection becomes many UI nodes

Do not hand-write one component call per record. Keep the records as data, transform each record with JavaScript, and give React a stable identity for every sibling.

Data array
→
filter() if needed
→
map() to JSX
→
Stable key
→
Rendered list

This is a data transformation pipeline. React receives the resulting JSX array; it does not require a special looping syntax.

Read the code

Three JavaScript ideas in one component

const products = [
  { id: "p-1", name: "Notebook", price: 8 },
  { id: "p-2", name: "Pen", price: 2.5 },
  { id: "p-3", name: "Desk lamp", price: 24 },
];

function ProductList({ products }) {
  const listItems = products.map(({ id, name, price }) => (
    <li key={id}>
      <span>{name}</span>
      <strong>${price.toFixed(2)}</strong>
    </li>
  ));

  return <ul>{listItems}</ul>;
}
  1. map() transforms. It calls the callback once per product and returns a new array. Each callback result is one <li>.
  2. Destructuring shortens access. ({ id, name, price }) unpacks those properties from the current product object.
  3. JSX uses JavaScript values. Curly braces insert name and the formatted price into the markup.
  4. key preserves identity. React uses the stable id to match an item when the array is sorted, inserted into, or filtered.

Why not the array index?

An index describes a position, not the item. When an item is inserted, removed, or moved, positions shift and React can associate the wrong existing UI with the new data.

Why not Math.random()?

A random key changes on every render. React then treats every item as new, which can recreate the DOM and discard local input or component state.

What about mutation?

map() does not mutate the original array. That matters especially for arrays in React state, where the next state should be a new array.

One subtle arrow-function bug

item => (<li>...</li>) implicitly returns. With a block body—item => { ... }—you must write return.

Check your understanding

Answer before reading the explanation

Question 1 of 4

What does map() return?

Choose one answer.

map() creates a new array containing the callback's return value for each source item; it does not itself return one element.

Question 2 of 4

What should a key identify?

Choose one answer.

A key gives React stable identity for an item among its siblings. A persistent ID from the data is usually the right source.

Question 3 of 4

What does object spread create?

Choose one answer.

Object spread copies enumerable own properties into a new object, but nested objects still share references; it is shallow, not a deep clone or freeze.

Question 4 of 4

What does destructuring do?

Choose one answer.

Destructuring unpacks array elements or object properties into distinct variables or function parameters. It does not change the source object by itself.

Make it stick

Give the interview answer from memory

Without looking back, write three or four sentences answering: “How would you render a list of products in React, and how would you choose the key?” Mention map(), one JavaScript concept, and one key pitfall.

Reveal a model answer

“I keep products in an array and use map() to transform each product into an <li>, using destructuring or property access to read its fields. I give each list element a stable key from the product’s persistent ID, not the array index or a random value, because React uses the key to match items when the collection changes. If the list is in state, I use non-mutating methods or spread to create the next array.”

Mini debugging exercise

Find the two bugs

const listItems = products.map(product => {
  <li key={Math.random()}>{product.name}</li>;
});

What are the two problems? Write your answer before opening the explanation.

Reveal the explanation

The arrow function has a block body but no return, so every callback returns undefined. The random key also changes on every render; use a stable key from the product data, such as key={product.id}.
