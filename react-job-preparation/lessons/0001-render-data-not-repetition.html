Three JavaScript ideas in one component

function ProductList({ products }) {
  const listItems = products.map(({ id, name, price }) => (
    <li key={id}>
      <span>{name}</span>
      <strong>${price.toFixed(2)}</strong>
    </li>
  ));

  return <ul>{listItems}</ul>;
}
  1. map() transforms. It calls the callback once per item and returns a new array; each result is one <li>.
  2. Destructuring unpacks. ({ id, name, price }) binds those properties of the current object.
  3. JSX uses JavaScript values. Curly braces insert name and the formatted price.
  4. key preserves identity. React matches items by the stable id when the array is sorted, inserted into, or filtered.

Pitfalls interviewers probe

  • Index as key: an index is a position, not the item. Insert, remove or move, and React can attach the wrong existing UI to the new data.
  • Math.random() as key: changes every render, so React treats every item as new and can recreate the DOM, losing input or component state.
  • Mutation: map() does not mutate the source. Arrays in React state need a new array for the next state.
  • Arrow bodies: item => (<li>…</li>) returns implicitly; item => { … } needs an explicit return.

Cards

In a React list, what should an element's key identify?

A key gives React stable identity for an item among its siblings. A persistent ID from the data is usually the right source.

In an interview: how would you render a list of products in React, and how would you choose the key? Mention map(), one JavaScript concept, and one key pitfall.

map() the products array into <li> elements, reading fields with destructuring. Use the product's persistent ID as the key, not the index or a random value, because React matches items by key when the list changes. If the list is in state, build the next array without mutating (non-mutating methods or spread).

const listItems = products.map(product => { <li key={Math.random()}>{product.name}</li>; });

This React code has two bugs. What are they?

The arrow function has a block body but no return, so every callback returns undefined. The random key changes every render; use a stable key from the data, such as key={product.id}.

A todo list uses the array index as key. Each row has an uncontrolled text input. After deleting the first todo, the typed text appears next to the wrong todos.

Why does this happen, and what is the fix?

The index is a position, not the item: after a deletion every item's index shifts, so React reuses the existing rows (and their input state) for different data. Use a stable ID from the data as the key.
