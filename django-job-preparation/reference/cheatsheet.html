Request lifecycle (0001)

Request
→
Middleware
→
URLconf
→
View
→
ORM / template
→
Response

Middleware wraps the path and may short-circuit it. A view can return HTML, a redirect, an error response, JSON, or another response type.

  1. URLconf selects. Maps URL path expressions to view callables; patterns checked in order, first match wins.
  2. The view decides. Receives the request, returns an HttpResponse. Not the same thing as a template.
  3. The model describes data. A Python class that generally maps to a table; the ORM is the access API.
“Django receives the request through its middleware stack, resolves the URL against the root URLconf in order, and calls the first matching view with an HttpRequest plus captured parameters. The view does the work, possibly querying the ORM or rendering a template, and returns an HttpResponse, which travels back through middleware to the client. A missing match or exception goes to Django's error handlers.”
Common correction: not “Django finds the template from the URL.” The URL resolves to a view; the view may render a template, redirect, return JSON, or produce another response.

Source: Django URL dispatcher.
